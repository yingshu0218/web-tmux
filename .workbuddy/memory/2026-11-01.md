  （零新增依赖。官方 addon 的默认 handler 还是 `window.open` 不带 noopener）。

- 行为：只认 `http(s)://` 与 `www.`；普通左键点击新标签打开；Shift/Alt 按住不跳；
  折行 URL 按 isWrapped 逻辑行拼接；宽字符按 cell 列映射（不用字符串下标）。
- `styles.css` 未改：`xterm.css` 已内置 `.xterm-cursor-pointer { cursor: pointer }`。

**验证**（`.workbuddy/artifacts/2026-11-01-终端链接可点击/`，含 raw-verify.log）：
pointer 命中 60 点、点击触发 `window.open → http://<TEST_HOST>:9400/`、
拖选与 Shift+点击均为 0 次打开、console 无错误；纯逻辑单测 6 条 + 折行用例全绿。

**两个新踩的坑**（已写进 artifacts README 与 AGENTS.md）：
1. xterm 的 `pointerCursor` 是 `classList.add('xterm-cursor-pointer')`，**不是 inline style**。
   第一版探针读 `element.style.cursor` 恒空 → 扫出 0 命中，差点误判成 provider 有 bug。
2. CDP 探针登录后仍必须 `Page.reload()`，否则 SPA 停在登录页，`#/terminal` 深链会被踢回，
   报「终端没有挂载」。

## 终端选中复制（同日第二个功能）

- 用户报「拖动选中后马上取消」。**真实根因不是取消，是压根没选上**：tmux `mouse on` 时 xterm 会
  `_selectionService.disable()`，把拖动翻译成鼠标事件发给 tmux。两次对照实测：shell 直连 `hasSelection=true`
  且 2 秒后仍在；attach tmux `hasSelection=false`。
- 新增 `web/src/selection.ts`：① 每帧输出后复查 `term.modes.mouseTrackingMode`，发现被 tmux 重新打开就补
  DECRST（只骗前端，不动 tmux 设置）；② 滚轮自己构造 `\x1b[<64/65;1;1M` 转发给 tmux，保住 copy-mode；
  ③ `mouseup` 时选中即复制（http 站点 `navigator.clipboard` 不可用，走 `execCommand` 兜底）。
- **两条死路已验证无效，别再试**：`mousedown` 里 write + 补发合成 mousedown（write 异步，合成事件 xterm 不认）；
  直接改 `_core.coreMouseService._activeProtocol='NONE'`（selection service 是初始化时一次性 disable 的）。
- **顺手修掉一个自己引入的 bug**：`execCommand` 兜底会 focus 隐藏 textarea，移除后焦点掉到 body，
  选完文本再打字没反应。已还原焦点到 `term.textarea`。
- 点击不再上报 tmux（点 pane 失效）—— 刻意的代价，已写进 AGENTS.md。
- 验证：`artifacts/2026-11-01-终端选中复制/`（五项断言全过）；链接功能回归通过；性能全场景在基线内
  （高速输出 0.8% / 样式 16.2 每 s）。
