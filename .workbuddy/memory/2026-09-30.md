## 分屏（双屏/四分屏）问题核实 —— 用户报「格子内没有关闭按钮 / 第二格不能选其他会话」

测试站 `http://<TEST_HOST>:9301/`（admin / <TEST_PW>），部署产物 = 本地 HEAD `f1dc427`。
用零依赖 CDP（headless Chrome + `Input.dispatchMouseEvent` 真实点击）实测，脚本在 `/tmp/tw-verify/`（临时，未入库）。

### 结论

**问题 1（格子内没有关闭按钮）—— 属实，但「能关，只是入口不在格子上」**
- 分屏后 `.slot-head` 的子元素实测只有 `["slot-dot on","slot-sel"]`（空格子是 `["slot-name"]`），
  `headButtons: []` —— 格子头里一个按钮都没有，更没有 ×。
- 关闭 × 只在顶部标签条 `.term-tabs .term-tab .close`。
- 实测「在双屏下点标签条 × 关掉正在显示的 work」→ 该格正确恢复成 `+ 选择会话`
  （`emptyPlaceholders:1`，slot i=1 `empty:true`）。**功能链路是通的**，缺的是格子内的入口 +
  格子名与标签条顺序没有视觉对应关系，用户得抬头找同名标签。

**问题 2（第二格不能选其他会话）—— 属实，且比"不能选"更糟**
- `.slot-sel` 的 options 数据源是 `tabs.filter(x => x.key !== t.key && !slots.includes(x.key))`
  —— 遍历的是**已打开的终端连接**，不是服务器上的会话（`groups`）。
  所以它只能列「已打开、但当前没显示在任何格子里」的终端。
- 实测（双屏占满 + 共 2 个终端）：每格下拉 = `[当前会话, "选择其它会话…"]`，**只有两项**。
  用户点开看到"只有我自己"，主观感受就是不能选。
- 反证机制：再开一个终端（临时 shell）后 work 被挤出格子 → codebuddy 那格下拉变成
  `[codebuddy, work, 选择其它会话…]`，多出来的 `work` 正是"已打开但未显示"的终端。
  证实：**这个下拉是「已打开终端切换器」，不是「会话选择器」**。

**额外发现（比上面两条更该修）—— 重复选择导致半屏空白且无法自助恢复**
- 弹窗里把**已在另一格显示的会话**选给当前格 → `openTab(t, slotIndex)` 里 `setSlots` 让两格指向同一 key，
  而 `tabs.map` 落位走 `slots.indexOf(t.key)`（只返回第一个匹配）→ 只有一个 `.term-slot` 拿到 order，
  **另一格直接消失成空白色块**（截图已留证：顶栏两个标签都在，右半屏是纯色块，
  没有任何"选择会话"入口）。弹窗对已在别格显示的会话**既不标记也不禁用**，很容易踩。

**顺带发现 —— 开新终端会静默顶掉最后一格**
- 格子已满时点侧栏「＋ SSH 直连」，走 `revealTab` 的「无空位就替换最后一格」分支，
  实测 `work` 被挤出格子（`display:none`）而新 shell 占了右格；work 连接仍在但无提示。
  用户观感是"我开了个新终端，原来那个不见了"。

### 建议修法（待用户拍板）
1. 格子头加 ×，语义定为「清空这一格」（摘 slots，连接保留在标签条）——与标签条 × 的"关连接"区分。
2. `.slot-sel` 数据源从 `tabs` 换成 `groups`（服务器+会话，分组），已在别格显示的标记/禁用。
3. `openTab(t, slotIndex)` 里若 key 已存在于 slots 其他位置，先腾空/交换，避免两格同 key。
4. 开新终端优先填空格；无空格时提示"已放入标签条"，不静默顶掉。

- 用户确认修哪几条 → 然后一起改 + 部署测试站验收（闸门未放行，未推送）

## 用户报「浏览器功耗特别大、笔记本发热」→ 做了一次 CDP 量化诊断

**没有改任何源码**，只测量 + 留了一份可复跑的探针。

### 测量方法（新建的可复用工具）

`.workbuddy/artifacts/2026-09-30-浏览器开销诊断/`：

- `browser-load-probe.mjs` —— 零依赖 CDP 探针，对测试站分场景采样
- `raw-measurement.log` / `raw-animation-ab.log` —— 原始日志
- `README.md` —— 完整报告（数据、根因、真机复核步骤、修复清单）

指标：`Performance.getMetrics` 前后差值的 `TaskDuration ÷ 秒数` = 渲染进程主线程占用；
配合 `RecalcStyleCount` / `LayoutCount` / `JSHeapUsedSize` / longtask。
杀手锏是 `Emulation.setEmulatedMedia({prefers-reduced-motion:'reduce'})` 做 A/B 归因。

### 结果

| 场景 | 主线程 | 样式重算/s |
|---|---|---|
| 会话总览页（2 卡片） | 4.7% | 60.0 |
| 终端页 · 未开会话 | 4.4% | 60.1 |
| 终端页 · 1 个空闲终端 | 6.6% | 60.0 |
| 终端页 · 高速输出 1.2MB | 8.0% | 69.8 |
| **A/B：动画开启 → 关闭** | **4.1% → 0.2%** | **60.1 → 0.1** |

**根因**：`web/src/styles.css:380` 的 `.dot.online { animation: pulse 2s infinite }` 动画的是
**`box-shadow`（不可合成属性）**，导致每帧重算样式 + 重绘。**占空载 CPU 的 95%**，
且因为「页面永不空闲」而阻止整机进入低功耗态 —— 这正是笔记本持续发热的典型来源。

### 顺带排除的

- **轮询不是主因**：关掉动画后整页 0.2%，说明本规模（1 台机 2 会话）下全部轮询只值 ~0.2%。
  代价随会话数线性放大（总览页每张可见卡每 3s 一个请求 + 一次 innerHTML 整体替换）。
- **xterm 不是主因**：动画关掉后，挂着已连接的终端 + 光标闪烁，主线程只有 **0.13%**。
  目前是 DOM 渲染器（`canvas=0`），高速输出时脚本仅 0.4%。
- **未测到**：GPU / 合成器 / `WindowServer`。`.rail`（240px×满高）与 `.statusbar`
  （满宽×64px，`blur(32px) saturate(1.15)`）的毛玻璃代价在这边，需真机复核。

### 待用户拍板的修复清单

P0 把 `.dot.online` 的 `box-shadow` 动画改成 `::after` 的 `transform/opacity`（或直接删掉脉冲）；
P1 加 `document.hidden` 门控 + 给 `SessionCard`/`PreviewCard` 加 `memo`；
P2 上 `@xterm/addon-webgl`、服务端合并输出改二进制帧、收紧 `backdrop-filter`（须真机 A/B）。

### 两个踩过的坑（已写进 probe 注释与 skill）

1. Chrome 启动**必须带 `--no-sandbox`**：沙箱里 Chrome 自己的 sandbox 起不来 →
   `GPU process isn't usable. Goodbye.` + SIGTRAP，表现成「CDP 连上就断 / 命令超时」。
2. 页面内 `fetch` 登录后**必须 `Page.reload()`**：Cookie 有了不等于应用知道 ——
   `App.tsx:202` + `useEffect(checkAuth)` 只在挂载时读一次，不重载就永远停在登录页，
   **我因此白跑了一整轮测量**（所有场景其实都在测登录页）。
3. 探针的账号变量别叫 `USER` —— 被 shell 占用（值是 `infinity`），登录静默 401。改用 `TW_USER`。

### 两条新沉淀（已写进 AGENTS.md §3.2/3.3）

1. **打 Tag 不会动 `latest`** —— `.cnb.yml` 的 `"v*": tag_push:` 只推版本号与短 SHA。
   所以「给已上线的那次提交补版本号」是安全的操作，可以放心做。
2. ⚠️ **`<短SHA>` 不是稳定的回滚锚点** —— 同一次提交的 push 构建与 tag 构建是**两份镜像**
   （源码相同、digest 不同），却**都往同一个短 SHA tag 上推**，后跑的覆盖先跑的。
   本例 `b631372d` 就从 `ddd33dc7…` 变成了 `59445756…`。要钉版本用 `:v0.4.0`。
