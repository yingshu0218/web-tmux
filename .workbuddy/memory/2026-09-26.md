## 修复本机 git + 首次推送 CNB（用户选方案 2，实际走了更好的方案 3）

  直接报 `Error: You have not agreed to the Xcode license.`。这条弯路已写入 AGENTS.md 警示
- **实际可行方案**：`/usr/bin/git` 只是 Xcode 的 shim，但系统里有两个**不受 shim 许可检查影响**的真实 git：
  - `/Library/Developer/CommandLineTools/usr/bin/git` → 2.50.1 (Apple Git-155) ← 采用
  - `/Applications/Xcode.app/Contents/Developer/usr/bin/git` → 2.54.0 (Apple Git-157)
- 修复两步（缺一不可，均为用户级、不在项目内）：
  1. `ln -sf /Library/Developer/CommandLineTools/usr/bin/git ~/.local/bin/git`
     （`~/.local/bin` 在 PATH 中优先于 `/usr/bin`，实测确认）
  2. **关键且易漏**：`mkdir -p ~/.local/libexec && ln -sfn /Library/Developer/CommandLineTools/usr/libexec/git-core ~/.local/libexec/git-core`
     —— Apple git 用 `_NSGetExecutablePath()` 推导 exec-path 且**不解析 symlink**，
     于是去 `~/.local/libexec/git-core` 找 helper。不做这步的表现是：
     `commit` 完全正常，但 `fetch/push` 报 `git: 'remote-https' is not a git command`
- **修正一个此前的错误结论**：之前把下面这类报错归因为「heredoc 内 zsh 展开」，
  实测发现 Bash 工具其实以 **POSIX sh** 执行（zsh 的 `${(s.:.)PATH}` 会报 `Bad substitution`），

## 滚轮行为排查（只调研，未改代码，待用户拍板）

**现象**：`work` 滚轮 = 向上翻看会话记录；`demo-agent` 滚轮 = 调出历史输入。

**根因（实测）**：两个会话的 tmux `mouse` 选项不一致 —— 服务器全局 `mouse off` + `history-limit 2000`，但 `work` 有**会话级 `mouse on`**（外加 `status off`，历史遗留的手工覆盖），`demo-agent` 继承全局 off。

**验证方式**：建两个 `mouse` 值与真实会话完全一致的复刻会话（refuse 触碰在用的 work/demo-agent，避免 tmux 把窗口 resize 到浏览器尺寸），用 CDP 抓 `Network.webSocketFrameSent/Received` 逐帧比对。

| | mouse on（=work） | mouse off（=demo-agent） |
| --- | --- | --- |
| 滚轮期间浏览器发出的字节 | 30 帧全是 `\x1b[<64;82;14M`（SGR 鼠标） | 30 帧全是 `\x1bOA`（**= ↑ 方向键**） |
| 实际效果 | tmux 进 copy-mode，界面右上角出现 `[145/301]`，**能滚到连接之前**的行 | 浏览器把滚轮翻译成 ↑ 发给窗格 → bash readline 把**命令历史调进输入行** |
| 本地回滚行数 | 0 | 0 |

**关键事实**：tmux 会话的 xterm 本地回滚**恒为空**（`scrollHeight == clientHeight`，即使连上之后再灌 200 行输出也不增长）——因为 tmux 自管屏幕、用光标定位重绘，从不使用终端原生滚动。所以「交给浏览器自己滚」这条路在本项目里**实际不存在**，`mouse off` 时 xterm 必然退化成发方向键。

**copy-mode 吞键已确认**：`tmux copy-mode -t S` 后 `send-keys 'echo KEY_REACHED_PANE' Enter` → `pane_in_mode` 仍为 1、窗格零回显。默认滚轮绑定是 `copy-mode -e`（滚回底部自动退出）。

**顺带发现的配置缺陷**：
1. `~/.tmux.conf` **不存在** → `BASE_TMUX_CONF`（含 `set -g mouse on`、`history-limit 10000`）从未推送到这台机器；当前跑的是 tmux 默认值
2. `pushTmuxConf()`（tmux.js:142）只 sftp 写文件，**不 `source-file`、也不 `set -g`** → 即使推成功，已在运行的 tmux server 也不生效（只影响其后新建的会话）
3. 移动端 PgUp/PgDn 按钮发 `\x1b[5~`，但 tmux root 表**无 PageUp/PageDown 绑定** → 透传给窗格，bash 忽略 = 实际无功能

**CDP 脚本坑（本轮新增）**：
- 终端页 `Terminal.tsx:192` 打开会话后会 `history.replaceState(null,'','#/terminal')` 抹掉 query。所以「先设 hash 再 reload」会把刚建的标签页一起清掉，页面停在「尚未打开终端」（脚本会误判成功能坏了）。正确顺序：**先 `location.reload()` 清状态，再设 hash** 让应用自己建标签
- 在被沙箱约束的环境里，node 子进程内 `execSync('ssh ...')` 会被拦（无输出、status 1）→ 需要服务器侧动作时改走应用自身 UI（发送框）驱动
- 判断「滚轮是否被吞」不能只比对首尾行文本（会误判），要看 `pane_in_mode` 或全屏文本

## v0.1.12 attach 强制 UTF-8（中文显示为下划线的修复）

**怎么发现的**：在做多 socket 演示时往新会话里发了中文，浏览器终端里显示成 `____`（4 个下划线 = 2 个宽字符）。

**根因**（`ws.js`）：`ssh exec` 是非交互的，环境里**没有 LANG/LC_ALL**（实测 `locale charmap` = `ANSI_X3.4-1968`）。
tmux 据此认定 client 不支持 UTF-8 → **把 pane 里的宽字符输出成 `_` 占位**。

**证据链**（关键：pane 内部完全正常，坏的是 attach 输出这一段）：
- `tmux -L twprobe capture-pane -p | od -c` → `344 270 255 346 226 207`（= 真 UTF-8「中文」）✓

## 查 CNB 构建用量（顺带纠正两个错误结论）

**用户问**：我的账号有多少次构建次数。

**查到的口径**：CNB 社区版配额单位是**核时**不是次数 —— 云原生构建 **160 核时/月**、
云原生开发 **1600 核时/月**，月底清零不叠加，超额 0.125 元/核时。CLI **没有配额接口**，
只能网页看（组织 > 设置 > 用量管理）。核时 ≈ duration(s) × 核数 / 3600，
与构建状态接口报的 `metricCoreHours` 吻合（50s × 8 核 ≈ 0.1）。

**统计结果**（blueteam0715，遍历 13 个仓库）：全量 595 条构建记录，其中
**只有 66 条是真正的 CI**（push 63 + tag_push 3），**529 条是 `event: vscode`**
（云原生开发/WebIDE 会话，单条 duration 可达 8–18 小时，走开发额度、不占构建额度）。
其中 workhub 一个仓库就 480 条全是 vscode；web-tmux 9 条 = push 3 + tag_push 2 + vscode 4。

**两个纠正**：
1. **AGENTS.md §8 与用户级 MEMORY 里「Bash 工具以 POSIX sh 执行」是错的** ——
   实测报错前缀 `(eval):N:`、glob 不匹配 `no matches found`、多行变量不按换行分词，
   三处都是 **zsh** 特征。最实用的后果：`for r in $MULTILINE` 会把整个多行串当成一个元素
   （报 `operation not permitted: /tmp/bcnt-a\nb\nc.txt`），必须用
   `while read -r r; do … done <<< "$VAR"`。两处文档都已改正。
2. **CNB 构建记录里混杂 vscode 会话** —— 统计「构建次数」必须按
   `--event push|tag_push|crontab` 过滤，否则数字会被放大近 10 倍（595 vs 66）。

**CLI 限制**：`--repo` 必填（无法账号级一次查询）；`--createTime`/`--endTime` 实测不生效（恒 total: 0）。
