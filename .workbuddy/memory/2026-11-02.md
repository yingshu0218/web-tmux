## 终端：取消自动复制 + 右键菜单

用户反馈两点：① 拖动只要选中，复制自己来；② 会话内右键要应用自己的菜单，不是浏览器原生菜单。

- `web/src/selection.ts`：**删掉「选中即复制」**（mouseup 那套）。现在只做两件事：
  挡掉 tmux 的鼠标上报让拖动走本地选择、把滚轮翻译成 SGR 发给 tmux。
  `copyText` 导出，新增 `copyTermSelection(term)`（复制 + 还原焦点）。
- `web/src/views/Terminal.tsx`：`rightClickSelectsWord: false`（xterm 默认值是 `isMac`，
  macOS 上右键会把选区改成一个词）；`.term-pane` 上 `onContextMenu` → `preventDefault()`
  → 弹应用菜单。菜单项：复制（无选中禁用）/ 粘贴 / 全选 / 清屏 / 重连 / 关闭终端。
- `web/src/views/Overview.tsx`：`CtxState` 导出、items 加 `disabled`、`ContextMenu` 支持禁用态；
  **顺手修了既有 bug** —— 关闭监听改成只在 `!e.defaultPrevented` 时关，
  否则 React 18 的 `#root` 委托比 `window` 先跑，「菜单开着再右键」会先开新菜单再被关掉。
- `web/src/styles.css`：`.ctxmenu button:disabled` 样式。

细节决定：**「清屏」发 `Ctrl+L` 而不是 `term.clear()`** —— 后者只抹前端画布，
下一次输出/resize 又刷回来，用户会以为没生效。

验证（`artifacts/2026-11-02-终端右键菜单/raw-verify.log`，五项全过）：
自动复制 0 次、右键弹自定义菜单且不破坏选区、菜单「复制」写剪贴板 1 次返回 true、
无选中时「复制」禁用、Cmd+C 等价的 copy 事件能拿到 clipboardData。

回归：链接点击通过；性能全场景在基线内（高速输出 1.7% / 样式 17.3 每秒，上限 3% / 20）。

## 脱敏 + 推 GitHub 公开镜像

用户要求「ip 地址、口令、域名都要删掉」后再推 `yingshu0218/web-tmux`（**public**）。

- 全仓库替换 45 处：`<TEST_HOST>`(17)、`<PROD_HOST>`(3)、`<TG_HOST>`(2)、`<CLIENT_IP>`(1)、
  `<PROD_DOMAIN>`(14)、`<PW_DOMAIN>`(1)、`<BASE_DOMAIN>`(2)、`<TEST_PW>`(6)。
  保留 127.0.0.1 / 0.0.0.0 与平台域名（cnb.cool、docker.cnb.cool、npm registry）。
- 真实值挪到 `.workbuddy/local-env.md` 并 **gitignore**（本地可查、绝不入库）。
  ⚠️ 以后写 memory/AGENTS 时要用占位符，别把真值写回去。
- **GitHub 只推单提交、不带历史**：本地历史里有脱敏前的提交，直接 `git push` 会连旧值一起公开。
  做法是 `git archive HEAD` → 临时目录 `git init` → 单提交 → `--force` 推 main。
  固化成 `scripts/push-github.sh`（带门禁：命中非回环 IPv4 / `.fun` 域名就中止）。
- CNB 仓库是 **Private**，历史保留原样。

**两个新坑**：

1. **macOS 的 `grep -E` 不支持 `\b` 词边界**（GNU 扩展）。门禁第一版写了 `\b(...)\b`，
   结果整个过滤失效 → 127.0.0.1 也被判成「公网 IP」，直接拒推。
2. **heredoc 里的反引号会被当成命令替换**：提交信息里写了 `` `<TEST_HOST>` ``，
   而 heredoc 没加引号 → 报 `syntax error near unexpected token`，消息被截断。
   改用 **引号版 heredoc** + `__PLACEHOLDER__` 事后 sed 替换变量。

GitHub 侧连通性：git 的 https 走不通（`Empty reply from server`，环境有代理但 git 没配），
**SSH 是通的**（`ssh -T git@github.com` → `Hi yingshu0218!`），所以 remote 用 `git@github.com:`。
